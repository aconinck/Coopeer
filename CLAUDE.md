# Coopeer

Sports discovery app — find a game nearby or join a club that plays every week.
Think "Airbnb for local sports." Launch market: Bentonville, AR. Sports: **soccer, pickleball and trails** for now.

Every screen requires an account (phone number + SMS code, no password); signed-out users only
see the welcome screen. Players tap "I'm in" on a one-time game ($7 drop-in) or join a club (monthly),
and anyone can start an open game or create a club (Figma "Criando Equipe" / "Criando Partida").

## Domain model — Place · Club · Game

- **Place**: where people play. **Every map pin is a Place**, never a club or a game.
- **Club**: a recurring group ("Every Fri · 8 PM"). Join once (code, QR, link or "Join club"); its games land in Schedule.
- **Game**: one occurrence at a place and time. Hosted by a club, or open (`clubId: null`) — a game never
  requires a club. RSVP with "I'm in". Create via `/create/game` (optionally `?club=`, `?pitch=` or `?sport=`).

Visual language that teaches the difference — keep it consistent:
- Games are always shown as a `GameRow` card: soft tinted `Tag` (sport or Live • Club/Open game) with the going avatars on the right, a big title, quiet meta lines (day · start – end, place · club), spots left as a big number and the action as a pill (I'm in / Join now / You're in / Full).
- Clubs are always shown with a rounded-square **ClubLogo** and a "Club" KindTag.
- Use `GameRow`, `ClubRow`, `ClubCard` from `src/ui/Rows.tsx`; never hand-roll another list item for these.

Map markers keep **places** and **activity** visually apart (`src/map/PlacePin.tsx`):
- A **place** (park, field, courts, trail, community center) is a calm neutral badge with a kind icon (`placeKinds`). Always there.
- **Activity** (a game live now or later today) is a loud pill floating above the place: a red circle with the sport icon + pulse for live (no text), brand orange pill with the time otherwise.
Place names fade in as you zoom; the selected pin lifts and the others dim.
Verified clubs (`Club.verified`) always show the blue `VerifiedBadge` next to the name.

Places have a kind, the sports you can play there (`Place.sports`) and optional licensed `photos` (credit them;
never invent image URLs — without photos `PlaceHero` shows an illustration). Picking a place when creating a
club or game shows `src/map/PlacePickerMap.tsx` (small map with the sport's place badges: tap one to pick it, picking from the list glides the map there) above `src/ui/PlaceResults.tsx`: Coopeer places first ("On Coopeer"), then OpenStreetMap
results from Photon (`src/lib/geocode.ts`, debounced, US only, biased to Bentonville) that `store.addPlace`
saves as new places. Never use Nominatim for autocomplete (its policy forbids it).

## Design system (patterns, use these before writing new UI)

References: AllTrails (map, places, badges), Strava (activity cards, stats), Airbnb (sections, profile card), Uber (grouped settings).

- **Rhythm**: a screen is a stack of `Section`s (`src/ui/Layout.tsx`): `SectionHeader` (title, one-line caption, optional
  underlined "See all") plus content, `layout.sectionGap` between sections. One header per section, no dense paragraphs.
- **Gutter**: everything aligns to `layout.gutter` (16). Horizontal card lists use `Rail`, which bleeds to the edges and snaps.
- **Hierarchy per card**: 1) media/cover, 2) title, 3) one secondary line (label2), 4) `StatRow` of big numbers,
  5) footer (avatars, tags). At most one status pill per cover corner.
- **Cards** (calm style: warm `bg`, white `card` with no outline and a whisper of shadow, radius 26, generous padding, soft tinted pills, one pill CTA bottom-right): `GameRow`, `ClubCard` (logo + verified, name, members, next-game pill), `ClubRow`, `PostCard`, `SportStatCard`. All use `card` from `Display`.
- **Picking a sport** (sign-up, create club, create game): always the `SportTile` row from `StepFlow` (icon + name, fills with the sport color). Never text chips.
- **Numbers**: `StatRow` (Strava stats); `ProgressBar` for anything with progress.
- **Rows**: settings and menus use `ListGroup` + `ListRow` (`IconTile` + title + optional subtitle/value + chevron).
- **Media**: every image/video sits in `MediaFrame` with a `media` aspect token (landscape 16:9, square, portrait 4:5,
  tall 3:4) and fills it (`FillImage`, or `fill` for video). Never letterbox, never a black backdrop. Use `fill`
  (explicit width/height 100%), not `absoluteFill`, for images and video: on web they ignore left/right/bottom.
- **Color**: neutral by default; color carries meaning. Sport color only when a sport is selected or for sport identity on
  covers; brand orange for primary actions and upcoming activity; red only for LIVE and destructive; blue only for
  verified; gold/silver/bronze only for achievements.
- **Profile** (yours and everyone's): identity + four numbers (Games · Hours · Places · Clubs), "Sports" rail (`SportStatCard`: games and hours), achievements (`AchievementBadge`), clubs, then account `ListGroup` on your own. Every number is DERIVED, never typed in: `computeStats()` in `src/state/profile.ts` runs over the games a player was "going" to that ended (not canceled) plus their club count; achievements are plain thresholds over that (`achievementsFor`). `usePlayer(id)` gives the same result for you and others (Supabase: `api.fetchPlayer`, which reads ended RSVPs separately because the store only keeps recent games; demo: derived from the store). "Played" = RSVP'd going to a game that ended, there is no check-in. No levels, skill trees, goals, wins, MVPs or miles: if a number cannot be computed from games already recorded, do not show it. People are tappable (`useDetailNav().player(id)` / `open.player(id)`): attendee lists, club members and feed post authors open `PlayerDetail` in the sheet; your own id goes to the Profile tab.

## Bottom sheet

Everything tapped on the map or in a list (place, game, club, who's going) opens in the **global
bottom sheet** (`src/ui/Sheet.tsx`, mounted once in `app/_layout.tsx`). It snaps to half/full by drag
velocity, rubber-bands at the top, keeps the ActionBar pinned to the visible bottom, and navigates
inside itself (slide in/out) with a back button. Detail content lives in `src/details/*` and renders
through `DetailLayout` + `useDetailNav()`, so the same component works in the sheet or as a page.
Open it with `open.place/game/club(id)` from `src/lib/nav.ts`; "Your Clubs" uses `open.clubPage(id)`.

## Action placement rules (every screen)

1. A screen's main action lives in the bottom **ActionBar**: `[SecondaryButton] [PrimaryButton]`, optional caption.
   Exception, matching the Figma: hero screens and the "club found" sheet use a full-width pill with a text button below.
2. Step-by-step flows (login, team code) use `StepScaffold`: back/close + progress bar, big title, round **NextButton** bottom-right.
3. The top-right header holds at most **one** control: `MoreMenu` ("…", or `icon="add"` for "+").
4. Details open in the bottom sheet (`open.*`); inside a detail use `useDetailNav()` so navigation stays in the sheet.
5. Destructive actions always confirm (`confirmDestructive`).
6. Login only when acting: wrap actions in `session.requireAuth(() => ...)`.

## Motion

Use only the tokens in `src/constants/motion.ts` (Apple's duration + bounce spring model, WWDC23).
Bounce 0 by default (≤0.1 for small choice controls), no scale "pops", lists just fade with a tiny
capped stagger, gestures hand their velocity to the spring. Haptics only for selections, sheet
detent snaps and outcomes (success/error) — never for ordinary button taps. Always honor `useReducedMotion()`. Never put `entering`/`exiting`/`layout` on the same
`Animated.View` that has an animated transform/opacity — wrap it. No custom springified `ZoomIn` entering on map pins: on web it leaves a stale `position:absolute; top` and detaches pins from their anchor.

## Code rules

1. Colors, type, spacing, radii only from `src/constants/theme.ts` (`flow` tokens hold the Figma step-flow measurements).
2. TypeScript strict, no `any`. `StyleSheet.create`; inline styles only for dynamic values.
3. Build screens from `src/ui` components; add to the kit instead of duplicating patterns in a screen.
4. English UI strings only (US-first).
5. No extra features without asking — keep scope tight.
6. Must work on iOS, Android and web; Expo Go compatible (no custom native modules).
7. Before pushing: `npx tsc --noEmit` and `npx expo export --platform web` must pass (CI runs both).
